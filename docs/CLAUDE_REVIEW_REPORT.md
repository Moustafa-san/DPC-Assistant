## 1. الخلاصة التنفيذية

الملف الأصلي قوي كأساس دائم لـ Claude Code: يغطي المنتج، التقنية، مصدر الحقيقة، المال، الأمن، RTL/PDF، الاختبارات، Git، والبوابات. لا أوصي بإعادة كتابته من الصفر.

لكن لا ينبغي اعتماده كما هو؛ توجد تعارضات جوهرية بينه وبين قرارات المالك الأحدث، وبعض الإشارات إلى الملفات والحالات أصبحت قديمة. أعددت نسخة مقترحة `CLAUDE.md.proposed` بالإصدار 0.2.0، ولم أستبدل الملف الأصلي. وافق المالك على PRD، لكن PRD الحالي يحتاج ملحق تغيير يعكس القرار الأحدث الخاص بالمصادقة.

## 2. نتائج ذات أولوية

### P0 — يجب إصلاحها قبل اعتماد CLAUDE.md

1. **Guest Mode يتعارض مع قرار المالك الأخير.**
   - المصدر الأصلي `PROJECT_DOCUMENTATION.md` وPRD يصفان تجربة الأدوات دون حساب.
   - المالك أوضح الآن أن Landing → ابدأ الآن → إنشاء حساب/دخول (مع Google) → استخدام الأدوات.
   - يجب أن يمر المسار الرئيسي عبر المصادقة، وألا يُسمح بتجاوزها عند غياب مفاتيح Supabase.
   - لكن المالك لم يحسم صراحةً هل يوجد CTA ثانوي مستقل لتجربة Guest؛ لذلك لا يجوز إعلان إلغاء Guest Mode أو الإبقاء عليه نهائياً. يبقى الخيار الثانوي والـ merge قرارين مفتوحين.
   - يلزم إنشاء ADR-012 وتحديث PRD وUX وArchitecture وData Model وThreat Model وImplementation Plan وGate criteria.

2. **رسالة غياب إعداد Supabase غير صحيحة بعد قرار المصادقة الإلزامية.**
   - النص الحالي يقول إن التطبيق يعمل كضيف عند غياب المفاتيح.
   - التوصية: Landing والصفحات العامة تعمل، لكن Auth والأدوات المحمية تعرض حالة إعداد واضحة ولا تسمح بفتح التطبيق دون مصادقة.

3. **ترتيب مصادر الحقيقة يحتاج ضبطاً.**
   - يجب ألا تعامل ADR مقترحاً أو مفتوحاً كقرار نافذ.
   - يجب أن يذكر الملف أن PRD وافق عليه المالك، وأن أحدث توجيه صريح للمالك يتقدم على نصوص PRD القديمة المتعارضة حتى يُحدّث PRD رسمياً.

### P1 — يلزم إصلاحها قبل Gate 2

4. **الهوية البصرية غير متسقة بالكامل.**
   - الملف يذكر `Location Red` و`Studio Dark` و`Daylight High Contrast`، بينما اتجاه المالك الأحدث Premium Editorial Studio بعاجي/بيج/زيتي.
   - يجب حذف السمات المتعارضة كقرارات أساسية، وعدم إدخالها دون موافقة. يمكن دراسة وضع تباين عالٍ كميزة وصول منفصلة بعد الاختبار.

5. **قسم الملفات المفقودة قديم جزئياً.**
   - حزمة Gate 1 الحالية تتضمن مجلد `ADRs/` و11 ADR.
   - `UX_DESIGN.md` v0.2.0 وخطة المنتج متاحان ضمن ملفات المشروع.
   - لكن توفرها في سياق ChatGPT لا يثبت أنها موجودة داخل جذر مستودع Claude Code. يجب التفريق بين الملف المرفوع والملف المنسوخ للمستودع.
   - `AI_DEVELOPMENT.md` وملف `AI_DEVELOPMENT_STANDARD.md` الأصلي لا يزالان غير مثبتين.

6. **شروط Gate 1 تطلب إغلاق كل ADRs.**
   - هذا واسع أكثر من اللازم؛ بعض القرارات تخص Gate 4 أو Gate 5.
   - التوصية: إغلاق القرارات التي تمنع تأسيس المشروع، وتوثيق الباقي كـ Deferred مع Gate المسؤول والمالك وشروط إعادة فتحه.

7. **قرار Auth يحتاج دقة أكثر.**
   - UX v0.2 يذكر البريد/كلمة المرور وGoogle OAuth.
   - وثيقة المنتج الأصلية تذكر Magic Link أيضاً.
   - يجب تسجيل البريد/كلمة المرور وGoogle OAuth كمسار مطلوب وفق UX، وترك Magic Link قراراً مفتوحاً حتى يعتمد المالك ذلك.

### P2 — تحسينات مهمة

8. **التخزين المحلي مع بقاء Guest Mode قراراً مفتوحاً.**
   - يجب أن يكون IndexedDB cache والـ sync queue معزولين لكل حساب مصادق.
   - يلزم تحديد سلوك logout وتبديل الحساب حتى لا تظهر بيانات حساب سابق لمستخدم آخر على الجهاز نفسه.
   - لا تبنِ Guest merge الآن؛ حدّد نطاقه فقط إذا اعتمد المالك مسار Guest ثانوياً.

9. **التشفير الاحتياطي.**
   - تثبيت PBKDF2 بالاسم وحده غير كافٍ؛ يلزم تحديد KDF والمعاملات والإصدار واختبار الاستعادة عبر ADR. أبقيت PBKDF2 مرشحاً لا قراراً نهائياً.

10. **المصفوفة الأمنية.**
    - ASVS_CONTROL_MATRIX مصفوفة موضوعية أولية وليست mapping كاملاً لكل ضوابط ASVS. يجب إبقاء هذا القيد واضحاً والتحقق من الإصدار والمعرفات الرسمية قبل التنفيذ.

11. **الاختبارات.**
    - bun:test وnpm ما زالا اقتراحين/قرارات ADR؛ لا تكتب أنهما معتمدان نهائياً قبل إغلاق ADR-001 وADR-002.

12. **الـ 8 tabs.**
    - أسماء التبويبات ليست مثبتة في مصدر المنتج. لا تحول الاستنتاج الحالي إلى قرار ثابت قبل اختبار تدفق الهاتف.
